# Офлайн-анализ записей NeuroScope

## Запуск

Нужен Python с зависимостями из `requirements-offline.txt`. Установка требуется один раз. Для последующих запусков достаточно локальных файлов и этого окружения. Из корня проекта выполните следующие команды.

```bash
.venv/bin/python -m pip install -r requirements-offline.txt
.venv/bin/python -m tools.neuroscope_offline --records records --output reports/offline
```

В Windows используйте `.venv\Scripts\python.exe`. Откройте `reports/offline/index.html` в браузере. Графики и таблицы лежат рядом с ним. Сервер, подключение к повязке и Capsule SDK для запуска анализа не требуются.

```bash
.venv/bin/python -m tools.neuroscope_offline --records records \
  --manifest reports/offline/input_manifest.json --output reports/offline-replay
```

Каждый свежий запуск фиксирует длины исходных файлов до расчёта. Для продолжающейся записи берётся префикс каждого потока до последней полной строки. Снимки отдельных потоков могут расходиться на ещё не сброшенные порции. `input_manifest.json` хранит длины и SHA-256, а также небольшие JSON-метаданные снимка для повторного расчёта после закрытия записи. При повторе добавленные байты игнорируются, а повреждение зафиксированного префикса останавливает анализ. `run.json` хранит параметры, версии пакетов и контрольные суммы кода. Исходные каталоги читаются только для чтения. Локальные результаты и манифест содержат идентификаторы и время сеансов и хранятся в игнорируемом Git каталоге `reports/`.

## Подтверждённая схема записи

- Заголовки ЭЭГ и `meta.json` накопленных записей указывают два биполярных отведения O1–T3 и O2–T4. `server.py` запрашивает биполярное подключение и получает отсчёты через `get_raw_value` из Capsule SDK. Номинальные частоты в метаданных составляют 250 Гц для ЭЭГ, 100 Гц для ФПГ и 250 Гц для MEMS. Анализатор берёт частоту каждого потока из соответствующего `meta.json`. При отсутствии частоты спектры не строятся. [Код регистрации ЭЭГ](../server.py#L680), [код метаданных](../recording.py#L140)
- В версиях формата 2 физическая шкала ЭЭГ, ФПГ и MEMS обозначена `sdk_native_unverified`, а сопротивление записывается как `ohm_as_sdk`. В ранних метаданных единицы отсутствуют. Ранний код в `0a097db:recording.py` округлял ЭЭГ до четырёх знаков, текущий сохраняет числа с 17 значащими цифрами. Для имеющихся данных PSD выражается в SDK-u²/Гц, мощность в SDK-u², доля безразмерна. Преобразование в мкВ требует отдельно подтверждённого масштаба. [Текущая запись отсчётов](../recording.py#L328)
- Путь записи передаёт `get_raw_value` без программного фильтра ЭЭГ. Параметры аналоговых и внутренних цифровых фильтров повязки или SDK в имеющихся метаданных отсутствуют. Калибровка и рассчитанные SDK показатели идут отдельными записями. Офлайн-расчёт удаляет линейный тренд внутри каждого окна и применяет окно Ханна. Спектральный notch и полосовой фильтр ЭЭГ не применяются. [Код получения и записи отсчётов](../server.py#L680)
- `sample_index` — порядковый номер строк рекордера. `ts_unix` — оценка из времени получения пакета хостом с обратным распределением отсчётов по номинальному периоду. `ts_iso` передаёт то же время с миллисекундной точностью и смещением часового пояса. При наличии `eeg_batch_timing` в `metrics.jsonl` доступны границы пакета по шкале SDK. Их можно проверить на согласованность с номинальным шагом, а аппаратная привязка к событиям остаётся неизвестной. [Код времени пакета](../server.py#L680), [схема метрики](../recording.py#L350)
- `events.jsonl` содержит `ts_unix`, `ts_iso`, тип и поля события. Журнал различает запуск и закрытие записи, подключение, калибровку, точечные чекпоинты и их правки, серверные фазы протокола и вложенные события лаборатории. Лаборатория хранит оценку времени браузера `at_ms` и время получения сервером `server_received_ms`. Длительность, заданная протоколом, хранится отдельно от наблюдаемых границ. [Схема событий](../recording.py#L318), [серверный протокол](../experiments.py#L142), [лаборатория](../experiment_lab.py#L402)

`host_long_gaps` считает шаги хоста больше трёх номинальных периодов с учётом округления до микросекунды. `host_expected_rows` — диагностическая оценка из размаха host-time. Обратный шаг, длинный интервал и расхождение этой оценки со счётчиком сами по себе не доказывают потерю отсчётов. Непрерывность индекса рекордера проверяет сохранённые строки. Для проверки более ранних потерь нужно время SDK или отдельный аппаратный счётчик пакетов. При наличии границ SDK проверяются только наблюдаемые пакеты. Межпакетный шаг больше номинального на `max(2 мс, половина периода)`, неположительный шаг или несогласованная длительность пакета отмечаются отдельно.

## Спектральный расчёт

Каждое полное окно длительностью 4 с берётся с шагом 2 с в исходном порядке. Частота берётся из метаданных, поэтому для доступных записей окно содержит 1000 отсчётов и шаг частотной сетки составляет 0,25 Гц. Вычисляется односторонняя `scipy.signal.periodogram` с периодическим окном Ханна, линейным detrend и `scaling="density"`. Отсчёты через известные разрывы индекса или времени SDK и окна с NaN/∞ дают пустые PSD в обоих вариантах. Данные не сортируются по времени хоста, пропуски остаются пустыми, восстановление или добавление отсчётов не выполняется.

До скрининга средняя PSD включает все вычислимые окна. После скрининга средняя PSD включает прошедшие правила качества окна при наличии минимум 15 окон на отведение. Неотброшенные окна с меньшим количеством видны на спектрограмме. Усреднение PSD выполняется в линейной шкале. Спектрограммы показывают `10·log10(PSD / 1 SDK-u²/Гц)` для неизвестного масштаба с одной шкалой цветов для обеих панелей отведения. Цветовые пределы берутся по 5-му и 99-му процентилям спектрограммы до скрининга с минимальным размахом 1 дБ.

Мощность полосы равна интегралу средней PSD методом трапеций с интерполяцией на границах. Полосы δ 1–4 Гц, θ 4–8 Гц, α 8–13 Гц, β 13–30 Гц и низкая γ 30–45 Гц. Для относительной мощности используется интеграл той же PSD по 1–45 Гц, если знаменатель положителен. Значение в CSV — доля, на HTML-странице — проценты. Регистрация выраженной компоненты 48–52 Гц полезна для диагностики качества, даже если эта компонента находится вне знаменателя.

Описательный скрининг использует плоские окна, менее 20 дискретных уровней, повторение ±0,8 SDK-u более чем в 0,1% окна при неизвестном масштабе и долю 48–52 Гц выше 50% от мощности 1–100 Гц. Дополнительно проверяются RMS после удаления тренда и RMS первых разностей. Верхний порог каждой метрики равен `max(медиана + 6 × 1,4826 × MAD, 8 × медиана)` в пределах сеанса и отведения. Плато около ±0,8 — наблюдаемый признак, физическое насыщение требует подтверждения. Контакт и MEMS проверяются по полноте отдельно, аппаратная синхронизация с ЭЭГ для их использования как маски не установлена. Отбор может изменить спектр, поэтому обе оценки и их знаменатели сохранены в отчёте.

## Условия и проверка классификаторов

Метки берутся из документированных пар событий фазы и завершённых запусков. Свободные чекпоинты, калибровка, незавершённые и конфликтующие фазы сохраняют свои исходные основания. Ретроспективные заметки из `reports/context/` не задают временных границ. Для поддерживаемых фаз границы сопоставляются с ближайшими значениями времени хоста в пределах ±0,1 с, затем используется внутренний отступ 1 с. Для подтверждённых пятисекундных задач «Виртуальная дверь» используется отступ 0,25 с. Для лабораторных меток дополнительно требуется совпадение оценок браузера и получения сервером в пределах 1 с. Такая привязка подходит для внутренних участков устойчивых блоков. Для измерения задержек реакции нужна аппаратная синхронизация.

Сеансы одного локального дня объединяются в одну группу. Сеансы, пересекающие полночь, связывают соответствующие календарные даты. Для каждого совместимого протокола и формата ЭЭГ тестируется целая группа, затем этот шаг повторяется по остальным группам. Состав групп фиксируется до извлечения независимых 4-секундных окон. Доли пяти полос по каждому отведению считаются локально в окне. Скрининг для моделей использует фиксированные правила, а нормализация по признакам оценивается отдельно на обучающих данных каждой итерации. Сравниваются самый частый класс, ближайший центроид и линейный Ridge с фиксированной L2-регуляризацией. Для оценки требуется не менее двух условий, не менее трёх групп и не менее шести пригодных окон на условие. Метрики описывают данный набор записей. Для переноса на новых людей нужно разделение по участникам.

В исследованном архиве есть один прерванный блок `eyes_open` длительностью около 29,469 с и нет парного блока `eyes_closed`. Для следующего опыта запишите оба условия минимум в пять разных дней, по два или больше блоков по 60 с на условие в каждый день. Начальный порядок меняйте между запусками, сохраняя число блоков и длительность. Для этого серверный протокол `eyes` поддерживает явный список фаз. Запишите реальные границы, проверьте контакт перед каждым прогоном, сохраните время SDK и MEMS и штатно закройте запись. Дополнительный день можно заранее оставить для отдельной проверки.
