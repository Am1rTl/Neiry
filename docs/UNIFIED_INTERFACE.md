# NeuroScope · единый интерфейс и подключение устройства

## Быстрое начало

Откройте http://127.0.0.1:8000 после запуска `bash start.sh --open` (Linux/macOS) или `start.bat` (Windows для анализа архивов). Все экраны находятся в **одном приложении**. Навигация в боковой панели:

- **Устройство** — искать, выбрать и подключить повязку, проверить состояние SDK, при необходимости калибровать.
- **Живой монитор** — ЭЭГ, ФПГ, акселерометр, доступные оценки SDK, контакт, ручная запись, метки.
- **Записи** — выбор сессии, анализ, воспроизведение без оборудования, ZIP-экспорт и удаление.
- **Обзор / Сигналы / Сравнение / Научная база / Протокол** — локальный исследовательский анализ и справочник.

Адреса `/live`, `/charts`, `/sessions` и `/more` оставлены для совместимости, но теперь перенаправляют на вкладки единой страницы.

## Без подключённой повязки

Запуск не инициирует Bluetooth-сканирование, соединение, калибровку или запись. Все существующие записи и расчёты доступны без SDK. **Нет устройства ≠ плохой сигнал**: интерфейс различает эти ситуации.

В автономном `preview.html` нет серверного поиска, WebSocket и подключения: это отдельный неизменяемый просмотр архива, встроенный в ZIP.

## Подключение шаг за шагом

1. Убедитесь, что повязка заряжена и включена, Bluetooth компьютера работает, устройство рядом и не занято другим приложением.
2. Если появляется «SDK не найден», установите Capsule SDK производителя, укажите `CAPSULE_SDK_DIR` и/или `CAPSULE_LIB` в переменных окружения. Сам ZIP не содержит нативной библиотеки SDK.
3. Откройте вкладку **Устройство**, нажмите **Найти устройство**. Только это действие начинает поиск.
4. После обнаружения выберите **Подключить** у конкретного серийного номера; соединение считается установленным лишь когда `Device.is_connected()` SDK подтверждает его.
5. После подтверждения перейдите в **Живой монитор**. В отличие от прежней версии, интерфейс не блокируется калибровкой.
6. По желанию запустите калибровку на вкладке **Устройство**. SDK baseline-калибровки тоже запускаются только по этому действию. Пропуск **не** помечается выполненной калибровкой.
7. Для сохранения сессии нажмите **Начать запись**. Новая версия **по умолчанию не записывает автоматически при подключении**. Для прежнего режима установите `RECORD_ENABLED=1` перед запуском.
8. Можно добавлять текстовые метки событий, остановить запись, отсоединить повязку и выбрать сессию на вкладке **Записи**.

## Состояния соединения

| Состояние | Значение | Что делать |
|---|---|---|
| `idle` | Соединения нет, ожидание действия | Нажать «Найти устройство» |
| `searching` | Запущен поиск через SDK | Подождать завершения окна поиска |
| `found` | Найден один или несколько серийных номеров | Выбрать нужную повязку |
| `connecting` | Команда Connect вызвана, подтверждения ещё нет | Дождаться ответа `is_connected()`, при необходимости отменить |
| `connected` | Нативный SDK подтвердил физическое соединение | Смотреть поток, калибровать по желанию, записывать |
| `disconnected` | SDK потерял ранее подтверждённую связь | Повторить поиск; либо разрешить авто-переподключение |
| `error` | Ошибка подключения/поиска | Прочитать сообщение и повторить действие |
| `sdk_missing` | SDK невозможно импортировать или инициализировать | Проверить путь, поставку SDK и совместимость ОС |

«Автоматическое переподключение» по умолчанию выключено. Если включить, программа пытается найти только **ранее подключённый и подтверждённый серийный номер**, а не любой новый прибор. Кнопка **Отключить** прекращает попытки и выключает авто-переподключение. Проверка `is_connected()` выполняется периодически, а временное отсутствие ЭЭГ-отсчётов отображается как «Нет свежих данных», но само по себе не выдаётся за Bluetooth-разрыв.

## Воспроизведение без повязки

Откройте **Записи** → **Воспроизвести**. Живые графики показывают **архивные данные**, помеченные как воспроизведение; это не текущая активность человека. На время подтверждённого физического подключения replay запрещён, чтобы не смешать архивные и живые измерения. **Анализ** из списка записей открывает выбранную сессию в разделе «Сигналы». Для обновления автономного превью после новых записей запустите `python scripts/build_preview.py`.

## API статуса (для диагностики)

```text
GET  /api/device/status
POST /api/device/scan
POST /api/device/connect                {"serial":"SERIAL_FROM_SCAN"}
POST /api/device/disconnect
POST /api/device/reconnect-settings     {"enabled":true}
POST /api/device/calibration/start
POST /api/device/calibration/skip
GET  /api/replay/status
```

Поля `connected`, `calibration_available` и `recording` характеризуют **текущую** сессию; данные из прошлой сессии после перезапуска не используются как доказательство подключения. Для невозможного действия API возвращает HTTP `409`, для отсутствующего SDK — `503`.

## Ограничения

Поиск, выбор, подтверждение и переподключение проверены на **подставном SDK** (без физического оборудования). Реальную работу BLE, поведение аппаратного SDK и особенности Windows/macOS **не удалось подтвердить**: исходный проект использует Linux `.so`. Архив, веб-API и Python-тесты работают без повязки. Для аппаратного теста необходима совместимая нативная поставка от производителя.

```bash
python -m unittest discover -p 'test_*.py' -q
```
