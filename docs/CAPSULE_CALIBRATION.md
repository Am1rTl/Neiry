# Калибровка и исследовательские данные Capsule 2.0.72

Откройте **Устройство → Настроить калибровку** после стабилизации контакта. Выберите режим, при необходимости прослушайте подсказки и нажмите **Подтвердить и начать**. Перед каждым этапом есть три секунды на смену положения глаз. Оставьте вкладку на экране и держите голову неподвижно. На открытых этапах смотрите на крест.

| Режим | Последовательность | Время сбора по примерам Capsule |
|---|---|---|
| Быстрый | Закрыть глаза | Около 30 секунд |
| Полный | Закрыть → открыть → закрыть → открыть | Четыре этапа примерно по 20 секунд |

Два нисходящих тона означают «закрыть глаза», два восходящих — «открыть». Тихий одиночный тон звучит примерно раз в 4,5 секунды сбора. Мелодия из трёх нот в конце означает, что Capsule вернул результат. Число секунд на экране — ориентир. Переходы полного режима запускаются по событию завершения этапа, успех — по итоговому событию с результатом. При потере контакта во время незавершённого этапа может понадобиться переподключение, поскольку публичный интерфейс калибратора не содержит команды отмены.

При включённом по умолчанию флажке запись начинается сразу после успешного результата NFB, пока Capsule продолжает собирать базовые уровни. Если запись уже запущена, результат добавляется в неё. Для записи самого калибровочного протокола нажмите **Начать запись** заранее.

## Что делает SDK

- `CNFBCalibrator.h` описывает индивидуальную частоту, частоту и мощность пика, его подавление, полосу частот и код ошибки. Python-пример использует быстрый режим. Python README и Dart-пример указывают порядок и длительность этапов полного режима.
- В поставке 2.0.72 `Calibrator.py` вызывает быстрый символ из метода `calibrate(stage)`. NeuroScope использует трёхаргументный `clCNFBCalibrator_CalibrateIndividualNFB` из C API. Доступность полного режима определяется при подключении.
- `Productivity` и `PhysiologicalStates` калибруют собственные базовые значения. По примеру поставщика их вычисление запускается после NFB. Базовые значения сохраняются отдельно как `prod_baselines` и `phy_baselines`, а итог NFB — в `calibration.json`.
- Для проверки движения у записи уже есть `mems.csv`. Сопротивление контактов остаётся в `resistances.csv`. Метки SDK о качестве и артефактах пригодны для сопоставления с этими потоками и сырой ЭЭГ. Семантику битов и пригодный порог оценки качества нужно подтвердить по записям.

## Как использовать в исследовании

Для проверки альфа-ритма с переключением положения глаз начните запись **до** полной калибровки. В `events.jsonl` у `calibration_cue`, `calibration_stage_start` и `calibration_stage_end` есть `run_id`, номер этапа и `eye_state`. Для спектрального сравнения берите сопоставимые окна внутри успешных этапов, вдали от смены инструкции. Аудио может повлиять на ЭЭГ, поэтому для отдельного контрольного прогона можно отключить звук или использовать отдельный протокол покоя. Метки отражают инструкцию, фактическое положение глаз программа не измеряет.

После калибровки откройте **Эксперименты → Виртуальная дверь**. Глаза открыты и при покое, и при воображаемом движении. Для анализа берите интервалы задачи из [протокола двери](DOOR_EXPERIMENT.md). Сравнивайте движение по MEMS и отмеченные артефакты между условиями, чтобы проверить, не различается ли качество записи. Результат индивидуальной частоты Capsule можно использовать для отдельного анализа альфа-ритма. Определение намерения требует размеченных испытаний и проверки на независимых сессиях.

В ZIP записи `metrics.jsonl` может содержать два дополнительных потока.

| Поток | Поля | Использование |
|---|---|---|
| `eeg_artifacts` | `sdk_timestamp_ms`; массив `channels` с `index`, `flags`, `quality` | Проверить, совпали ли подозрительные отрезки ЭЭГ с флагами SDK. `quality` читается как `float` по `CEEGArtifacts.h`, обходя ошибку типа в Python-пакете. |
| `eeg_batch_timing` | `first_sample_index`, `sample_count`, `sdk_first_ms`, `sdk_last_ms` | Привязать пакет к индексам `eeg.csv`, оценить разрывы и разброс времени доставки по отношению к меткам SDK. |

Основная шкала CSV по-прежнему основана на времени доставки пакетов, а маркеры интерфейса — на времени сервера. Метки SDK дают дополнительные данные для проверки задержек и пропусков. Перед их использованием для точной синхронизации стимулов проверьте происхождение и стабильность часов SDK на реальной повязке.
