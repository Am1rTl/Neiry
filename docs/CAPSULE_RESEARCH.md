# Диагностика Capsule 2.0.72

## Что показывает NeuroScope

| Поток | Источник | Что проверить |
|---|---|---|
| ЭЭГ | Сырые отсчёты SDK и сопротивление электродов | Посадка повязки, контакт, пригодность окон в автоматическом разборе |
| Метки артефактов ЭЭГ | Последнее событие `clCDevice_SetOnEEGArtifactsEvent` | Перед записью проверьте, поступают ли события и какие каналы пометил SDK. В архиве их можно сопоставить с сырыми отсчётами и движением. |
| Сырая ФПГ | Отсчёты оптического датчика | Поступают ли отсчёты. Сопротивление электродов ЭЭГ и оптический контакт SDK измеряют разные вещи. |
| Пульс и кардиоиндексы | Алгоритм Capsule | Оптический контакт, движение, флаги артефактов и доступность результата |
| Движение | Акселерометр и гироскоп SDK | Совпадают ли отклонения с этапом или подозрительным участком ЭЭГ |
| Продуктивность и физиологические оценки | Отдельные алгоритмы Capsule | Индивидуальная частота NFB и базовые калибровки. Для физиологических оценок SDK также требует базовый уровень продуктивности. |

Счётчик доставки WebSocket продвигается по количеству принятых отсчётов. Ось времени в браузере использует номинальный интервал дискретизации и сохраняет более крупные паузы между пакетами. При пакетной доставке она может расходиться с часами SDK и временной осью CSV. В CSV остаются времена, восстановленные по моменту доставки пакета, и индексы отсчётов. Для ЭЭГ доступны дополнительные метки Capsule в `eeg_batch_timing`.

Автоматический разбор при открытии записи показывает наличие потоков, пригодность окон, частые причины их отклонения, флаги артефактов и скачки времени между пакетами с последовательными индексами. Такие скачки позволяют найти участки для проверки, а для заключения о потере Bluetooth нужны измерения на устройстве с учётом свойств часов SDK. Физические единицы сигналов остаются единицами SDK, пока масштаб не подтверждён документацией или измерением. Графики подбирают диапазон по видимым отсчётам.

## Метки артефактов до записи

В `GET /api/device/status` поле `eeg_artifacts` описывает подписку текущего устройства. В сообщениях WebSocket с профилем `live` передаётся та же сводка. Её `state` принимает следующие значения.

| Значение | Что наблюдает сервер |
|---|---|
| `disconnected` | Физическое соединение ещё не подтверждено или уже закрыто. |
| `unsupported` | В текущей поставке SDK не удалось подписаться на событие. Остальные потоки доступны независимо. |
| `waiting` | Подписка установлена. Первого успешно прочитанного пакета с каналами ещё нет. |
| `fresh` | Получен пакет. `age_s` показывает время с его получения по монотонным часам сервера. |
| `stale` | С последнего пакета прошло больше `METRIC_STALE_SECONDS` (по умолчанию 8 секунд). Видны последние значения и их возраст. |

`channel_count` — число каналов в событии. В `channels` попадают первые 16 в порядке SDK. `index` начинается с нуля, `flags` содержит исходный код артефакта (0–255), `quality` — исходное число Capsule или `null` для нечислового результата. Ненулевое значение `flags` показывает наличие отметки производителя. Заголовок `CEEGArtifacts.h` не задаёт расшифровку битов, шкалу `quality` или интервал между событиями. Порог свежести характеризует давность получения. Решение о пригодности окна требует отдельной проверки сигнала.

Во время записи `metrics.jsonl` сохраняет все каналы события и `sdk_timestamp_ms`. При переподключении предыдущая сводка очищается. При воспроизведении архива поле WebSocket равно `null`. Для аппаратной проверки откройте живой монитор до записи, дождитесь первого пакета, затем начните запись и сопоставьте коды с потоком `eeg_artifacts` в архиве.

## Возможности Capsule и Mind Tracker

| Возможность | Что даёт для исследований NeuroScope |
|---|---|
| Версии прошивки и Capsule, физическая схема электродов, отдельные шкалы кардиографиков | Версии теперь появляются рядом с подключением и в метаданных новых записей. Все каналы сопротивления можно сравнивать на графике. |
| Спектр производителя | NeuroScope рассчитывает спектр самостоятельно. `clCDevice_SetOnPSDDataEvent` и `CPSDData.h` предоставляют альтернативную частотную сетку, мощности по каналам и границы полос Capsule. Для численного сравнения требуется сверить единицы, окна, нормировку и частоты в одном прогоне. |
| Метки времени ФПГ и движения | `CPPGTimedData.h` и `CMEMSTimedData.h` предоставляют `GetTimestampMilli` по индексу отсчёта. NeuroScope уже сохраняет границы пакетов ЭЭГ по времени SDK. Следующая проверка для ФПГ и MEMS — сравнить метки SDK и время приёма, измерить дрейф часов и частоту пропусков на устройстве. |
| Индивидуальная калибровка | Сервер сохраняет в `calibration.json` частоту пика и границы индивидуальной полосы из `CNFBCalibrator.h` при успешной калибровке. Их можно сравнивать между повторными сессиями с одинаковым протоколом. |
| Именованные интервалы и звуковая обратная связь в Mind Tracker | Метки действий пригодятся для повторяемых сравнений. Звуковую обратную связь можно проверить в отдельном протоколе с журналированием времени звуков. |

Публичный `CCardio.h` в версии 2.0.72 отдаёт сырую ФПГ, три кардиопоказателя и флаги качества. В настольном приложении есть дополнительные представления ФПГ. Их наличие в интерфейсе само по себе не подтверждает доступность через SDK.

Сигнатуры событий и типов сверены по заголовкам `CapsuleAPI/Linux/Include/` из поставки `Capsule_and_API_2_0_72_23_04_2026.zip`. Её `Linux/Lib/libCapsuleClient.so` экспортирует функцию подписки и четыре функции чтения для меток ЭЭГ, подписку на PSD и функции чтения времени ФПГ и MEMS. В изолированной Linux-проверке вызов `clCCapsule_GetVersionString` при отложенном связывании вернул `v2.0.72-6deee8423`. Для полной загрузки штатной Python-обёртки в этой среде не хватило совместимой библиотеки BlueZ-in-C. Доступность потока на конкретной повязке можно установить по фактическому поступлению событий.
