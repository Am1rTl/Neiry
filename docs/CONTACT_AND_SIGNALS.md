# Контакт электродов и достоверность живых показателей

NeuroScope не имеет отдельного датчика надевания повязки. Электрический шум, движение устройства и оптические данные могут поступать **без кожи**. Поэтому состояние BLE `connected`, присутствие отсчётов и калибровка — разные сущности.

## Новый процесс

1. Подключите повязку. Появится состояние **«Ожидаем реальные измерения сопротивления»**. Сервер не генерирует искусственных значений.
2. Наденьте повязку и поправьте волосы под электродами. UI покажет актуальные значения `get_value(i)` из `on_resistances` для каждого измеряемого SDK канала в кОм (при условии, что SDK возвращает омы, как ожидает существующая интеграция).
3. По умолчанию **каждый** из минимум двух каналов должен иметь конечное неотрицательное значение `< 1000 кОм` (порог хорошего контакта из инструкции Neiry). Значения `< 500 кОм` выделяются как более предпочтительные по локальным настройкам проекта. Только для последовательно хороших **разных callback** начинается таймер: 6 с и минимум 3 обновления.
4. Не было результатов, значение ∞/NaN, высокий импеданс или устаревший результат — кнопка калибровки неактивна, индикатор сбрасывается. На сервере повторно проверяется контакт при HTTP-запросе и непосредственно перед вызовом `calibrate_quick()`.
5. Только после успешной калибровки и свежей ЭЭГ показываются персонализированные оценки SDK; пульс отдельно требует свежего ФПГ, `skinContact`, `metricsAvailable` и отсутствия SDK-флагов артефактов.

**Ограничения:** сопротивление показывает электродный контакт по SDK, но не гарантирует, что устройство надето именно на голову, что все электроды находятся в правильных местах или что ЭЭГ не загрязнена помехами. После физической проверки используйте диагностику качества сигнала. Пороги — инженерные настройки приложения, не медицинская диагностика.

При отсутствии надетой повязки графики ЭЭГ/ФПГ по умолчанию пусты, а вычисленные метрики скрыты. Переключатель **«Показывать сырой поток без контакта»** отображает *настоящие* невалидированные отсчёты для диагностики. Это не моделирование сигналов мозга. Запись и эксперименты не стартуют без свежей ЭЭГ и подтверждённого контакта.

Настройки окружения:

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `CONTACT_READY_OHM` | `1000000` | Верхний порог по каждому измеряемому каналу, Ом (строго меньше) |
| `SKIN_WARN_OHM` | `500000` | Предпочтительный порог, Ом |
| `CONTACT_STABLE_SECONDS` | `6` | Непрерывный период хорошего контакта |
| `CONTACT_STALE_SECONDS` | `4.5` | Максимальный возраст измерения |
| `CONTACT_MIN_UPDATES` | `3` | Минимум отдельных SDK callbacks |
| `CONTACT_MIN_CHANNELS` | `2` | Число каналов сопротивления для готовности |
| `METRIC_STALE_SECONDS` | `8` | TTL вычисляемых полей SDK |

Показанные значения **не следует пересчитывать** из непроверенной SDK-шкалы другой модели устройства. Если твой вариант SDK выдаёт не омы, исправь преобразование единиц после аппаратной проверки, а не просто меняй подписи в UI.

Руководство производителя: https://neiry.ru/support/headband — раздел «Электроды и калибровка»: значения 0–3000 на экране; рекомендуемый порог ниже 1000 на каждом электроде.

## Возвращённые панели

Панели в едином мониторе: ЭЭГ два канала; ФПГ; ускорение по модулю; 3 оси акселерометра; 3 оси гироскопа; сопротивление каналов; пульс; индекс стресса SDK; индекс Каплана; пять состояний SDK; пять физиологических индексов SDK; четыре показателя производительности SDK; пять NFB-полос; две спектрограммы и диагностика качества. Все значения приходят из потоков Capsule SDK либо вычисляются из их необработанных отсчётов. Нет заглушек с синтетическими сигналами и жёстких нулей вместо отсутствующих результатов.

## Проверка без устройства

`python -m unittest discover -p 'test_*.py' -q` проверяет алгоритм готовности на контролируемых имитациях callback и UI/API-контракты. Это не проверка BLE, точности единиц или реальных электродов. Следующая обязательная проверка — на физическом устройстве при последовательности: на столе → надеть → стабилизировать → снять → переподключить → replay.
