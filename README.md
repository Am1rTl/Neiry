# NeuroScope

Локальная исследовательская лаборатория для записей Neiry Capsule: ЭЭГ, ФПГ, движение и контакт электродов. Интерфейс и документация на русском. Исходный код и исследовательская база находятся в репозитории; персональные записи и рассчитанные на их основе отчёты в публичный GitHub не публикуются.

В рабочей папке рядом с WebApp находится 3D-нейроатлас. После запуска сервера откройте [симулятор](http://127.0.0.1:8000/atlas/). Он принимает две ЭЭГ-пары через существующий WebSocket NeuroScope. Если порт отличается, добавьте к адресу своего сервера путь `/atlas/`. [Исходники и варианты запуска](../neuro-atlas/README.md).

## Запуск и локальные записи

После `git pull` запускайте `bash start.sh --open` (Linux/macOS) или `start.bat` (Windows). Приложение открывается без устройства и без калибровки. Данные записей находятся **только на вашем компьютере** в `records/` и не включаются в публичный репозиторий. Если у вас уже есть записи, оставьте их в `records/`: обновление Git их не затронет.

Для нового клона каталог `records/` создаётся автоматически при первом запуске. Экспорт JSON/CSV/HTML и автономная версия создаются локально из ваших файлов, а не публикуются в GitHub.

### Требования и способы запуска

Рекомендуется Python 3.12; проверено с Python 3.12.14. Интернет нужен только для первоначальной установки зависимостей. Сам анализ работает локально и не требует аккаунта, API-ключа или облачной модели.

#### Linux / macOS

```bash
bash start.sh --open
```

Скрипт создаёт `.venv`, устанавливает зависимости при их отсутствии и запускает приложение в текущем терминале. Откройте http://127.0.0.1:8000. Для завершения нажмите Ctrl+C; в другом терминале можно выполнить `bash stop.sh`.

#### Windows: анализ архива

Установите Python 3.12 с добавлением в PATH и запустите `start.bat`. Или выполните:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run.py --open
```

Аппаратная интеграция, перенесённая из оригинала, использует Linux-библиотеку Capsule `.so`. Для подключения устройства в Windows/macOS нужна соответствующая адаптация поставки SDK; офлайн-анализ архива от этого не зависит. Проверка с физической повязкой в этой среде не выполнялась.

#### Ручной запуск / другой порт

```bash
python -m pip install -r requirements.txt
python run.py --port 8001
python run.py --analyze
```

`--analyze` перед запуском проверяет кэш по содержимому файлов и пересчитывает изменённые записи. Прямой запуск `python server.py` также работает. Адрес по умолчанию ограничен `127.0.0.1`.

## Автоанализ архива

В истории записей можно сверить отчёты с исходными файлами. Обзор показывает, есть ли в записи завершённая пара условий для исследования альфа-ритма, сколько окон прошло контроль и какую следующую запись стоит сделать. В лаборатории «Альфа-ритм» можно запустить четыре пары со сбалансированным порядком и звуковыми подсказками. В отчёт также входит отдельная проверка узкой полосы около 83,33 Гц при частоте дискретизации 250 Гц. [Как читать результаты и повторить проверку](docs/ARCHIVE_READINESS.md).

## Чекпоинты во время записи

Во время записи нажмите **«Поставить чекпоинт»** или **Alt+M**. Время сразу сохраняется в журнале событий записи. Поле названия остаётся открытым, пока вы его не сохраните или не закроете. Закрытый без названия чекпоинт можно подписать позже через **«Чекпоинты»** в списке записей. Название можно изменить и после окончания записи.

## Парный анализ ЭЭГ

Живой монитор, обзор и сигналы сохранённой записи показывают сравнение биполярных отведений O1–T3 и O2–T4, когда хватает пригодных парных окон. Можно переключать частотные диапазоны и вращать 3D-схему электродов. Подробности расчёта и границы интерпретации описаны в [документации по парному анализу](docs/PAIRED_LEADS.md).

## Лаборатория экспериментов

Запустите NeuroScope, откройте `http://127.0.0.1:8000/#experiments` и выберите протокол. В деморежиме работают таймеры, зрительное задание, сфера обратной связи и журнал; для анализа записанной ЭЭГ выберите Neiry Headband и дождитесь готовности сигнала.

| Протокол | Что делать | Что смотреть в результате |
|---|---|---|
| Альфа-ритм | Пройдите пары блоков с открытыми и закрытыми глазами. Повторите в другой день. | Отношение мощностей по каждому затылочному отведению и число пригодных окон. |
| Зрительное обучение | Сделайте исходные замеры, тренируйте одну из двух ориентаций, затем пройдите итоговый и отложенный тесты. | Точность, медиану времени правильных ответов, порог различения 75% при достаточных данных и альфа-мощность всей задачи. |
| Нейрообратная связь | Пройдите исходный блок, живую обратную связь, контроль с заранее сохранённой траекторией и тесты без обратной связи. | Пригодные окна, медиану мощности и значения, показанные участнику. Для контроля сначала завершите живой блок с достаточным количеством пригодных кадров. |

### Как проверить пригодность альфа-блоков

Откройте **Эксперименты → Журнал сессий → Проверка альфа-ритма**. Таблица показывает для каждого блока и отведения принятые окна, причины исключения и покрытие проверки высокочастотной линии. Одно окно может иметь несколько причин. ВЧ-столбец показывает число окон с доминирующей линией среди окон, в которых удалось вычислить её долю. При срабатывании рядом видна частота пика в наиболее выраженном случае.

Для каждого неперекрывающегося окна 4 с программа рассчитывает спектр Welch с отрезками по 2 с (сетка 0,5 Гц при 250 Гц). Она находит максимальный пик плотности мощности между 65 и 95 Гц. Если в полосе ±1 Гц вокруг него сосредоточено более половины мощности 1–100 Гц, окно исключается. Это инженерная проверка качества записи. Для установления источника линии нужны повторные измерения. Для проверки требуется спектр до 100 Гц с положительной суммарной мощностью. Если проверить ни одного окна не удалось, в таблице стоит «Нет оценки». Для отношения закрытые/открытые в каждом завершённом блоке пары должно остаться как минимум три пригодных окна на одном и том же отведении.

Для размеченных фаз программа также проверяет, помещается ли всё четырёхсекундное окно внутри этапа за вычетом отступов (3 с в начале, 1 с в конце). На записях с пакетными метками SDK она сверяет непрерывность индексов, длительности пакетов и шаг часов SDK на стыках. В альфа-блоках от 30 с документированное сопоставление программных часов позволяет использовать разброс времени доставки до 250 мс вместо строгой проверки межотсчётных интервалов. Для старых прогонов без настроек нужна подтверждённая пакетная запись. При отсутствии пакетных меток сохраняется строгая проверка программного времени. Столбец причин показывает, какие проверки отклонили окна. Для измерения задержки стимула нужен независимый физический маркер.

В результате альфа-прогона раскройте запись в **Журнале сессий**. Для попытки с сохранёнными метками начала и прерывания показана отдельная таблица «Прерванные блоки». Она сообщает число проверенных окон и причины исключения. Отношение мощностей учитывает только завершённые фазы одной запланированной пары.

Используйте одинаковый код участника и настройки в повторных сессиях. Для сопоставления зрительных тестов зафиксируйте расстояние до экрана, ориентацию и число проб. В журнале доступны результаты, экспорт событий и ссылка на ZIP с сырыми данными. Во вкладке сравнения доступны завершённые сессии с одинаковым кодом, источником и настройками. Демо хранится отдельно от реальных сессий в интерфейсе.

Сессия с повязкой создаёт запись или присоединяет события к уже запущенной записи. При завершении останавливается запись, запущенная самой лабораторией. База экспериментов (`records/.experiment_lab.sqlite3`) сохраняет сценарий, метки и контекст; исходные сигналы остаются в своих подкаталогах `records/`. Для переноса истории между компьютерами скопируйте всю папку `records/`, включая базу. Сырые отсчёты записываются сервером независимо от браузерной отрисовки. События содержат программное время браузера и время приёма сервером. Для анализа реакций с точным временем появления стимула нужна отдельная аппаратная синхронизация.

Задания со стимулами ставятся на паузу при переключении вкладки или переходе в другой раздел NeuroScope. При возвращении текущая проба или блок повторяется в той же сессии. Серверные протоколы с таймером «Покой» и «Задача и восстановление» продолжаются сами.

## Обновление V3: живые показатели только после проверки контакта

Подключение по Bluetooth **не является подтверждением надевания повязки**. Вкладка «Устройство» теперь показывает реальные измерения сопротивления каждого канала Capsule SDK, состояние контакта и обратный отсчёт стабилизации. По умолчанию необходимо получить минимум три отдельных обновления сопротивления от двух различных электродов, держать значения ниже 1000 кОм непрерывно 6 секунд и получать свежие измерения. При снятии устройства или потере контакта готовность сбрасывается, а калибровка блокируется. **Физического датчика надевания нет:** хорошие сопротивления доказывают лишь электрический контакт в рамках SDK.

До подтверждения контакта ЭЭГ и ФПГ не показываются как проверенные сигналы, а вычисленные показатели SDK скрыты. Можно включить отдельную диагностическую опцию просмотра *сырых* реально полученных отсчётов без контакта (это шум/данные без гарантии их физиологического происхождения, не демонстрационные числа). После калибровки и подтверждения свежести SDK показателей они снова становятся доступны. Пульс дополнительно проверяется по `skinContact`, `metricsAvailable` и признакам артефактов SDK.

В едином живом мониторе восстановлены самостоятельные панели ЭЭГ, ФПГ, трёх осей акселерометра, трёх осей гироскопа, сопротивления, пульса, двух кардиоиндексов SDK, групп состояний и продуктивности, пяти NFB-полос и двух спектрограмм. Никакие несуществующие отсчёты не подставляются. Подробные критерии, единицы, ограничения и настройка порогов — [docs/CONTACT_AND_SIGNALS.md](docs/CONTACT_AND_SIGNALS.md). Проверка с физической повязкой всё ещё требуется.

## Обновление: лаборатория V2

Теперь в одной теме доступны расширенный живой монитор со спектрограммой и контролем качества, воспроизведение без полной загрузки записи в память, исследование выбранного участка и аннотации, управляемые эксперименты, история сопоставимых сессий, локальный PDF и опциональный экспорт EEG-BIDS. Метрики Hjorth и описательный спектральный наклон рассчитываются только для пригодного сигнала.

**Важное исправление Capsule SDK:** обход `DeviceInfoList` сделан по `range(len(info))`: несуществующий индекс больше не запрашивается, предотвращая известный SIGSEGV в `clCDeviceInfo_GetName(NULL)`. Для завершения сервера `stop.sh` использует SIGINT вместо SIGTERM, поскольку сторонняя нативная библиотека может перехватывать SIGTERM. Физический SDK необходимо дополнительно проверить на конкретной повязке.

[Подробно: обновление V2, инструкции и ограничения](docs/UPGRADE_V2.md).

## Разделы

- **Обзор**: выбор записи, качество, доказуемые наблюдения, ограничения, контекст пользователя.
- **Сигналы**: исходный фрагмент, спектр до и после скрининга, полосы, временные показатели, ФПГ, движение и контакт.
- **Сравнение**: описательное сопоставление сессий с явными знаменателями. Без диагнозов и популяционных норм.
- **Научная база**: 17 разделов, 22 метрики, 25 первичных/официальных источников.
- **Протокол**: четыре способа собрать более интерпретируемые данные в будущем.
- **Устройство** (`#device`): ручной поиск и выбор обнаруженной повязки, реальная проверка соединения, управление отключением/переподключением и необязательной калибровкой.
- **Живой монитор** (`#live`): ЭЭГ, пульсовая волна, акселерометр, контакт, показатели SDK, ручная запись и метки событий — в новой теме, без перехода на старую страницу.
- **Записи и replay** (`#sessions`): список сессий, воспроизведение архива без устройства, анализ, экспорт ZIP и удаление.
- **Эксперименты** (`#experiments`): три управляемых протокола, журнал, деморежим и сравнение измерений.

Все эти разделы находятся **в одной странице**. Старые ссылки `/live`, `/charts` и `/sessions` ведут в соответствующие разделы общей оболочки. Метрики SDK помечены как модельные оценки. Подробнее — `docs/UNIFIED_INTERFACE.md`.

Поля контекста заполняются ретроспективно: они не заменяют синхронные event markers и не меняют численные расчёты. Экспорт отдельной сессии доступен в JSON, CSV и HTML. Общий исследовательский отчёт — в PDF.

## Калибровка Capsule

Во вкладке **Устройство → Настроить калибровку** доступны быстрый этап с закрытыми глазами и полный цикл «закрыть → открыть → закрыть → открыть». Звуки подсказывают переходы и сопровождают сбор. При активной записи сохраняются метки этапов, результат NFB и доступные данные SDK о времени пакетов и артефактах.

[Как пройти калибровку и использовать данные Capsule 2.0.72](docs/CAPSULE_CALIBRATION.md).

## Контроль потоков и автоматический разбор

После успешной калибровки NeuroScope сразу начинает локальную запись и сохраняет результат NFB в сессии. Флажок в диалоге позволяет отключить автозапуск. Если запись уже идёт, она продолжается.

В **Живой монитор → Контакт и поток** сырая ФПГ, кардиоиндексы и базовые уровни SDK имеют собственные статусы. При открытии сохранённой записи **Автоматический разбор** отдельно показывает наличие сигнала и пригодность оценок, число принятых окон, артефакты и скачки времени SDK. [Подробности по потокам и обзор приложений Neiry](docs/CAPSULE_RESEARCH.md).


При воспроизведении график пульса SDK использует сохранённые флаги Capsule. При неподтверждённом оптическом контакте, артефактах или неполной информации о качестве интерфейс показывает причину. Сырую ФПГ можно посмотреть отдельно, а оценку пульса по отобранным окнам — в автоматическом разборе.

## Сбор ЭЭГ с виртуальной дверью

В разделе **Эксперименты → Протоколы с таймером → Виртуальная дверь** запустите протокол при активной записи. После успешной калибровки запись уже идёт, если в её настройках включён автозапуск. В каждом из 20 испытаний экран предлагает либо мысленно повернуть дверную ручку правой рукой, либо спокойно смотреть в центр. Держите глаза открытыми в обоих условиях. После последнего испытания нажмите **Завершить запись → Скачать ZIP**. Архив содержит исходные сигналы и временные метки в `events.jsonl`.

[Инструкция и формат меток](docs/DOOR_EXPERIMENT.md).

## Анализ архива

Первые расчёты сохранённых сессий идут по одной записи в отдельной очереди. Экран сравнения показывает прогресс и загружает сессии последовательно. Проверенные отчёты открываются из кеша. Контрольные суммы для кеша и отчёта вычисляются вместе, а изменения входных файлов проверяются перед публикацией результата.

В карточке «Ритмы ЭЭГ» на экранах «Обзор» и «Сигналы и метрики» можно посмотреть долю мощности по времени и короткие полосовые фрагменты для одного или всех отведений. Таблица сравнивает все отведения до и после отбора окон. Чтобы увидеть оцениваемые окна, которые отсеял скрининг, включите их на графике мощности.

## Нагрузка живого монитора

Монитор получает новые отсчёты пакетами до пяти раз в секунду. При подключении он запрашивает выбранное окно истории в пределах буфера сервера. Графики обновляются в пределах видимой области, а для длинных окон отображаются минимумы и максимумы на каждом участке. Диагностика ЭЭГ и спектрограмма рассчитываются по мере появления их карточек. Сервер переиспользует недавние результаты между вкладками, а на паузе воспроизведения — до появления новых отсчётов или перемотки.

В фоновой вкладке живой монитор отключает поток для отрисовки. При возвращении он заново получает доступное окно из буфера сервера. Пропущенные участки отображаются как разрывы. Сервер продолжает приём сигналов, калибровку и запись. CSV сохраняется с частотой устройства, а пакетная запись сокращает число блокировок при работе с файлами.

## Как устроен автоанализ

1. Читает сохранённые CSV и JSONL; проверяет полноту, индексы, время, конечность чисел, квантование.
2. Анализирует ЭЭГ в порядке отсчётов при частоте из metadata. Обратные шаги callback-времени не исправляются сортировкой данных.
3. Считает спектры окон с правильной односторонней нормировкой, проверяет артефакты и формирует явные причины исключения.
4. Выдаёт полосовую мощность и кандидат пика только при достаточных данных. Отсутствие результата отображается как отсутствие, а не ноль.
5. Оценивает пульс/исследовательскую PRV с отдельной проверкой качества. PRV по ФПГ не равна ЭКГ-HRV.
6. Описывает движение, контакт, калибровки и выходы SDK, сохраняя их происхождение.
7. Формирует воспроизводимый JSON с версией метода, параметрами, SHA-256 и ограничениями.

Анализ запускается при открытии записи, по кнопке пересчёта и в фоне после штатного завершения новой записи. Если приложение выключилось до завершения фоновой задачи, при следующем открытии запись будет обработана. Кэш инвалидируется по версии метода и содержимому входных файлов; вычисления вынесены из web event loop.

Доля прошедших окон — результат инженерных эвристик с перекрытием, не процент здорового мозга, не вероятность отсутствия артефактов и не точная доля чистого времени. Все пороги опубликованы в JSON. Порог 50 Гц и диапазоны частот не являются диагностическими нормами.

## Добавить запись

Поместите каталог `session_*` в локальную папку `records/` (не хранится в Git). Ожидаются `meta.json` с `sample_rates` и `channels`, `eeg.csv`, необязательные `ppg.csv`, `mems.csv`, `resistances.csv`, `metrics.jsonl`, `events.jsonl`. Пустые потоки допустимы. Пример структуры доступен в документации и коде; записи пользователей не хранятся в Git.

```bash
python analysis_engine.py --all --records records --output reports
python analysis_engine.py --all --records records --output reports
python scripts/build_preview.py
```

Физические единицы и масштаб необходимо подтвердить по вашей версии SDK. Новые записи сохраняются без прежнего округления EEG, с описанием происхождения времени. Метки времени пакетов SDK, если они доступны, экспортируются отдельно в `metrics.jsonl`. Для точной синхронизации со стимулами их свойства нужно проверить на устройстве.

## Подключение повязки

```bash
CAPSULE_SDK_DIR=/path/to/CapsuleAPI/Linux bash start.sh
```

Для подключения нужна поставка Capsule SDK от производителя. Приложение **запускается без устройства**: архив, анализ и replay доступны сразу. Откройте вкладку «Устройство», нажмите «Найти устройство» и выберите подтверждённый серийный номер; подключение не запускается автоматически. Калибровка возможна **только после подключения** и выполняется по явной команде пользователя. Запись по умолчанию начинается после успешной калибровки. Её также можно запустить вручную. Для запуска при подключении есть `RECORD_ENABLED=1`. При отключении потоковые данные сбрасываются; автопереподключение выключено по умолчанию и настраивается в интерфейсе. Пошаговые инструкции — `docs/UNIFIED_INTERFACE.md`, настройки — `config.py`.

## Проверка

```bash
python -m pip install -r requirements-dev.txt
python -m scripts.run_tests
```

Эта же команда выполняется в GitHub Actions. Набор использует заглушки Capsule SDK и временные каталоги для записей и отчётов.

Тестируются нормировка PSD (сохранение дисперсии), известные частоты, отсутствие/нечисловые данные, пропуски индекса, сетевые помехи, квантование, pulse/PRV, сохранение точности, strict JSON и API. Сам тестовый набор не является клинической валидацией алгоритма.

Для создания PDF из локальных записей: `python scripts/build_report.py`. Шрифты Open Sans/DejaVu ищутся в системных каталогах; персональные отчёты не добавляются в публичный Git.

## EDF: дополнительная возможность

Нужен `pyedflib`. Экспорт требует явного `--allow-approximate-timing`: он использует номинальную сетку и не восстанавливает аппаратное совмещение потоков. Неизвестные единицы сохраняются как `a.u.`, а не автоматически `µV`. Создаётся sidecar JSON с ограничениями. Для исследований времени предпочтительнее исходные CSV.

```bash
python edf_export.py records/session_... output.edf --allow-approximate-timing
```

## Границы интерпретации

Файлы содержат два биполярных отведения O1–T3/O2–T4. Это не карта функций всех отделов мозга. Приложение не определяет IQ, личность, «доминирующее полушарие», дофамин, диагнозы или лечение. Сведения о работе мозга в научной базе — общий контекст; конкретные выводы всегда относятся к измеренному сигналу и качеству записи.
